## 配额模型与一致性

以百分比（`0`–`100%`）统一记账，不再使用虚拟积分。模型相对权重决定每次调用的**标准消耗当量** $u$：Gemini 3.8 Flash 默认 1 倍，Gemini 基础 3 倍（Gemini 4 Carbon ×0.75、Argon ×1.15，Hydrogen 与 Orchestrator 暂用基础权重）；Claude Sonnet 5.5 / GPT-OSS 120B 默认 3 倍（旧版 Haiku / Mini / Nano ×0.4），Claude Opus 5.5 默认 8 倍；同时区分思考档位（Low ×0.6 / Medium ×1.0 / High ×1.5，未注明时按 Medium）。这些是本系统的估算先验，不是官方公布的消耗倍率。

当前模型分类：Carbon、Argon、Hydrogen、Flash 与独立名称 `Orchestrator` 归入 Gemini 池；Claude Opus / Sonnet 5.5 与 GPT-OSS 120B 归入第三方池。支持显示名（如 `Gemini 4 Hydrogen Medium`、`GPT-OSS 120B (Medium)`）与 CLI 名称（如 `gemini-4-hydrogen-medium`），保留旧版 Gemini Pro、Claude 和 Auto 的家族匹配。Hydrogen / Orchestrator 暂按 Gemini 基础权重估算，后续仍以母账号实际配额快照校准。未知模型返回 422，客户端会暂停新调用并向 stderr 提示，需要在 [`src/quota.ts`](../src/quota.ts) 更新分类。参考：[官方模型说明](https://antigravity.google/docs/models/)、[官方配额分组说明](https://antigravity.google/docs/cli/commands/usage/)。

两个模型池默认各有 **5 小时 100%、每周 100%** 的家庭配额上限，默认安全缓冲留白 `buffer_percent = 0%`。管理员可按百分比（如 A 50%、B 25%、C 25%）为成员分配份额；比例滑条支持 0–100% 按扣除缓冲后的家庭上限速算，也可对每个池与时间窗口单独微调百分比。给成员设置上限不会提前预扣家庭池额度。

### 请求前上下文感知预留与线性 Token 结算

- **请求前高分位预留（`/check`）**：结合本机转录或数据库上一轮已知会话上下文 Token 数 `contextTokens`，按 `max(1, (25,000 + 0.15 × contextTokens) / 50,000)` 放大预留当量（超过约 167k 上下文后上浮），乘以当前窗口转换率的安全上界 $k_{\text{upper}}$ 冻结百分比。剩余配额不足以覆盖高消耗模型预留时直接拒绝，但仍允许切换至预留装得下的轻量模型。
- **完成后分段线性无封顶结算（`/commit`）**：有效 Token 为 `500 + min(input, 25,000) + 0.2 × max(input - 25,000, 0) + 0.1 × cache_read + 5 × output`，每 50k 有效 Token 对应一倍模型权重。未缓存输入超过 25k 的部分按 0.2 倍计算，以降低缓存过期后重读上下文的单轮跳变；总消耗不设人工上限。未收到 Token 统计时按模型权重结算。这些系数是本系统估算规则，不是官方计费公式。

### 周期累积不等式区间校准

默认开启自动校准，两个模型池 × 两个时间窗口各自独立估计每标准当量消耗的官方比例区间 $[k_{\text{lower}}, k_{\text{est}}, k_{\text{upper}}]$，并以保守上界 $k_{\text{upper}}$ 参与准入和用量展示。没有有效样本时，1 当量初始保守上界对应 **5 小时额度的 0.1%**、**周额度的 0.025%**，且在等待官方首次批量跳变期间也会随安全累计当量自动向下收紧上界。

校准采用**周期累积守恒模型**：不再因分钟级 Cron 采样与进行中调用（`reserved`）重叠而丢弃锚点，而是持续累积周期起点以来的已完成当量 `done`，对在途预留 `pending` 与跨越边界调用 `span` 显式放宽区间不确定度，并对最近 20 秒内刚提交的记录施加延迟保护，防止上游百分比尚未刷新时低估 $k_{\text{upper}}$。遇到未记账突降、离线补记或额度回升时，先将已确认周期证据折入跨周期历史记忆（`hist_units` / `hist_fraction`），再重新锚定当前周期起点。

### 账期跟随官方 reset 与母账号门禁

每池的 5 小时和周用量分别跟随上游对应窗口的 `resetTime` 清零，保留历史流水、幂等身份和跨周期校准记忆。查询确认余额提前恢复到 100% 时也开启新账期。如果同一个周额度桶的余额明显回升，并且新的 `resetTime` 显示两次同步之间已开启一个 7 天窗口，则按推算的起点结转周用量，即使同步时余额已经低于 100%。普通余额回升或单纯修改 reset 时间不会误清零。进行中的调用继续占用预留，完成后计入完成时所在的新账期。

母账号在 15 分钟容错宽限期内若跨越了已知的官方 `resetTime`，系统自动按重置后满额过渡，直至下一次成功同步。若母账号未连接、授权失效或连续超过 15 分钟无法同步，所有新调用暂停。迁移 `0012_percentage_quota.sql` 将旧版 250 / 2000 积分平滑换算为 0–100% 百分比份额，保留母账号加密凭据、管理员与成员登录会话及成员令牌哈希，并重置早期积分制计数表。

`/check` 在单条 `INSERT … SELECT` SQL 中读取个人与家庭的累计已结算用量及有效预留并原子放行，避免并发检查一起超分配。普通成功调用不再额外重算个人、家庭余额；只有余额提示或拒绝详情需要这些展示数据。预留计入两个窗口，默认 15 分钟有效。`/commit` 通过成员、会话、调用序号的联合唯一约束将预留转为实扣，重复发送不重复计费；实扣时间取**服务端收到完成记录的时间**，修改权重不会改变已有预留或历史账单。

`Stop` 仅在 `fullyIdle: true` 时释放同一会话尚未完成的预留，避免后台任务仍运行时提前释放。崩溃未触发 Stop 的预留自动过期。超时后才返回的调用仍会补记实际用量，可能导致预算短时超出；可在管理页将预留有效期调整至最长 1 小时。

客户端每次主请求网络超时上限为 10 秒，以容纳冷启动时较慢的代理 / TLS 建连；所有主请求尝试共用 16 秒网络预算，后续尝试按剩余时间缩短。临时网络错误、HTTP 408 / 429 / 5xx 最多重试 2 次（总共最多 3 次尝试），重试使用同一调用标识和请求体，避免重复预留或扣分。退避等待为 200 / 400 毫秒，各加最多 99 毫秒随机抖动；遵守服务端 `Retry-After`，如果等待后剩余预算不足 1 秒则停止重试。鉴权失败、参数错误、额度不足和无效成功响应不重试。脚本硬截止为 16.5 秒，外层 Hook `timeout` 为 18 秒，避免外层提前杀死进程。安装提示词同时要求检查重试策略和这些时限。预检异常输出 `terminationBehavior: "terminate"` 暂停新调用；完成、释放异常仍输出 `{}`。完成记录在发送前写入本机待补记目录；后续 Hook 成功连接时最多尝试补记 10 条，每条补记只尝试一次、最多等待 10 秒，失败留待下次 Hook 补记，并受脚本 16.5 秒总时限约束。自动更新在补记之前尝试，下载同样最多等待 10 秒并受脚本总时限约束，避免慢网络下始终无法更新。只发送模型名、会话 ID、调用序号、可用的上下文与输入 / 缓存 / 输出 Token 计数以及明确失败标志，**不会发送提示词、工作目录、转录路径或内容**。改变成员令牌或服务地址后，旧目标的待补记记录不会归到新目标，需在改变凭据前尽量完成同步。

响应的 `Server-Timing` 中，`app` 为 Worker 处理耗时（包括等待 D1），`/health` 额外提供 `sql` 数据库执行耗时，便于与客户端 DNS、TCP、TLS、首字节时间对照。可按自己的 D1 主库位置配置 Worker Placement，减少预检两轮数据库访问的跨洲往返；示例配置不固定地区。

已结算当量按「成员 × 模型池 × 账期」维护累计值，以 0.001 当量为整数单位，避免不断加减造成浮点漂移。数据库触发器让账本和累计值在同一事务中更新，重复结算不重复累计，删除成员也保留其已用家庭额度。进行中的预留仍按到期索引读取，无需写入来清理过期记录。首次初始化、官方账期切换或提前重置时，按边界从保留的原始流水重建一次累计值；重建与并发调用互斥，边界发生竞争时返回可重试的 503。百分比转换率每次读取，调整校准不需要重写历史用量。

后台校准按窗口保存已处理到的完成时间和累计证据，仅扫描后续新增记录、最近 20 秒延迟保护区间和当前预留。已处理流水的修正、删除或迟到插入会同步修正累计证据；版本与账号锁阻止并发同步覆盖较新的证据。代价是每次结算多写少量累计行；页面查询始终只读少量汇总行与最近 80 条明细。

迁移 `0013_usage_query_indexes.sql` 缩小活跃流水扫描范围，`0014_usage_statistics_cache.sql` 添加成员历史索引，`0015_cumulative_usage.sql` 用累计用量取代此前的页面缓存，并增加增量校准与活跃状态。迁移保留已有成员、账本、令牌和加密凭据，首次使用时按原账本初始化累计值；`npm run deploy` 会先应用迁移。免费 D1 当日读额度已经耗尽时，需要额度恢复后才能执行远程迁移和验证。

## 能力边界

- 这是互信成员的客户端软限制，删除或修改 Hook 可以绕过，不是 Google 官方配额隔离或计费网关。
- 官方 `PostInvocation` 当前只定义“调用完成”，没有明确的 `success` / `error` 结果字段。因此当前实现按收到 PostInvocation 记账，不能承诺所有错误和取消都不扣分；若将来客户端提供明确失败标志，当前接口已支持释放预留。Stop 不会反向冲销已记账记录。
- 预留过期、丢失 PostInvocation、令牌更换前未同步都会限制统计的完整性。待补记文件丢失无法恢复；无人再次调用 Hook 时，也不会后台主动补记。
- 模型权重、Token 统计与自动校准仍属于估算，无法精确还原官方消耗，也无法保证官方池永不触发限流。
- 删除成员会从成员列表移除并拒绝新预检，历史流水与已用家庭额度保留，进行中调用仍可完成记账或释放。迁移 `0006_member_deletion.sql` 添加删除标记。
- 暂停成员会拒绝新预检；已经发起的调用仍能提交和释放。重置令牌会让旧令牌立即失效，先确保在途调用完成。
- 账本保留历史记录以保证长期幂等，目前不自动删除；仅活跃窗口参与限额。长期使用应观察 D1 存储和查询配额。
